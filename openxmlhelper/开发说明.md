# Open XML 助手开发说明

本文面向改 Word / Open XML 助手或接入它的 Main 开发者。具体行为以当前代码为准；本文只保留稳定边界。

## 定位

- 仓库根目录 `openxmlhelper/` 是独立 .NET 10 控制台，给 Electron Main 做 Word / Open XML。
- Renderer 不直连助手，不经过 preload。
- 主程序通过 `openXmlHelperService.runJob` 调用；Agent 通过 Pi 专用工具 `openxml` 调用同一套动作。不要把助手 exe 放进 PATH。

## 进程

- 长期挂着，一次只跑一个任务。Main 第一次提交任务时懒启动，应用退出时杀掉。
- 启动参数只有工作区根路径：`openxmlhelper --workspace <userData/workspace>`。
- 助手不创建任务编号目录；编号由 Main 分配。

## 通讯

管道只传开工和做完。stdin / stdout 各一行 UTF-8 JSON，无 BOM，换行只用 `\n`（Windows 也如此）。不要把文档正文塞进管道。

Main → 助手：

```json
{"v":1,"type":"run","job":"20260819153000-ab12"}
```

助手 → Main：

```json
{"v":1,"type":"done","job":"20260819153000-ab12","ok":true}
```

- `job` 只允许字母、数字、`.`、`_`、`-`，防止路径穿越。
- 失败也只回 `ok:false`。错因写在任务目录的 `result.json`。
- 信号无法解析时写 stderr，进程不退。
- 助手忙时对后到的任务写失败结果并回 `done`。
- 不加 shutdown 信号，退出靠 Main 杀进程。

## 任务目录

双方自己读写文件，不靠管道传内容。

`workspace/openxml-jobs/<job>/`

| 文件 | 谁写 | 含义 |
|---|---|---|
| `request.json` | Main | 至少包含 `action` |
| `result.json` | 助手 | 至少包含 `ok`；失败时写 `error` |

约定：先写齐输入再发 `run`；先写完 `result.json` 再发 `done`。

当前动作：

```json
{"action":"ping"}
```

```json
{
  "action": "list-blocks",
  "sources": ["technical-plan/tender-originals/xxx.docx"]
}
```

`list-blocks` 在任务目录写出 `blocks.json`，列出每块的序号、类型、是否标题和原文预览。

```json
{
  "action": "extract-chapters",
  "sources": ["technical-plan/tender-originals/xxx.docx"],
  "chapters": [{"id":"1","title":"施工组织设计","sourceTitle":"第五章 施工组织设计"}],
  "output": "technical-plan/bid-template.docx"
}
```

`extract-chapters` 按 Agent 给出的原文标题或块区间抽章：只有 `heading=true` 的原文标题可以使用 `sourceTitle`；非标题样式必须同时提供 `startBlock` 和 `endBlock`，助手不会为不完整块区间或非标题块自动推断结束边界。`title` 只用于模版里的章节名，缺少合法原文定位则失败。

抽章成功后会在输出 DOCX 同目录写出同名 `.chapters.json` 边车文件，例如 `technical-plan/bid-template-source.chapters.json`。文件格式为 `{version:1,chapters:[{id?,title,start_block,end_block}]}`；块号是目标 DOCX 正文中的 0 基序号，`start_block` 包含起始块，`end_block` 不包含结束块。字段扫描用它识别候选所属章节；文件缺失或无效时扫描失败并要求重新抽取章节。

```json
{
  "action": "scan-template-fields",
  "input": "technical-plan/bid-template-source.docx"
}
```

`scan-template-fields` 在任务目录写出单行紧凑的 `template-field-candidates.json`，顶层包含 `version`、`default_suggested_fill_by`、去重后的 `contexts` 和 `candidates`。`contexts` 项包含 `context_id`，并按实际内容提供 `chapter_name`、`table_title`、`column_header`、`group_title`；候选通过 `context_id` 引用上下文，并按需提供 1 基的 `row_number`、`column_number`。表格列号按 `gridBefore` / `gridSpan` 展开后的逻辑网格计算，空字段不输出；候选没有单独提供 `suggested_fill_by` 时使用顶层默认值。非表格候选按需输出原位置，表格候选使用结构上下文和行列定位，内部原位置仍参与稳定 `candidate_id` 的计算。候选只供普通模板 Agent 分类，不作为最终业务字段清单。

```json
{
  "action": "apply-template-fields",
  "input": "technical-plan/bid-template-source.docx",
  "output": "technical-plan/bid-template.docx",
  "fields_output": "technical-plan/bid-template-fields.json",
  "fields": [
    {"candidate_id":"c_xxx","name":"投标人名称","fill_by":"ai"},
    {"candidate_id":"c_yyy","name":"法定代表人签字","fill_by":"manual"}
  ],
  "ignored_candidate_ids": ["c_zzz"]
}
```

`apply-template-fields` 要求每个候选恰好归入 `fields` 或 `ignored_candidate_ids`。助手重新扫描源模版，按候选位置写入 `w:sdt`：业务 ID 保存在 `w:tag=yibiao:field:<id>`，字段名保存在 `w:alias`；AI 与人工字段都使用淡红底 `FCE8E6` 和黑字 `000000`。最终同时生成 `bid-template.docx` 和精简字段 JSON，相同 `name` 允许对应多个不同 ID。

上例是 Main 与助手之间的内部请求。Agent 使用 `openxml` 时只传 `{"action":"apply-template-fields","fields_file":"投标模版字段分类.json"}`；分类文件顶层包含完整的 `fields` 和 `ignored_candidate_ids`。正常路径在 `write` 写完分类文件后直接调用该动作，不需要另跑 Bash 或脚本预检。Pi 工具先读取 UTF-8 文件并执行 JSON/Ajv 结构校验；助手随后重新扫描源模版，检查候选是否遗漏、重复、交叉或无效，并检查 `fill_by` 和同名字段的一致性，写入内容控件后再执行 Open XML 与产物校验。失败时 Agent 根据工具错误修改同一份完整分类文件并重试；应用成功且产物检查通过后程序直接结束模版提取任务。

```json
{
  "action": "insert-body-html",
  "input": "technical-plan/template.docx",
  "target_id": "technical-plan",
  "image_max_width_percent": 90,
  "html": "<!-- yibiao:block -->\n<p id=\"p_001\">正文内容</p>\n<!-- yibiao:block -->\n<figure id=\"fig_001\" data-yb-generation=\"htmlImage\" data-yb-size=\"wide\"><template data-yb-role=\"prompt\">配图提示</template><img alt=\"质量控制图\" data-yb-asset-ref=\"generated-images/quality.png\"><figcaption>质量控制图</figcaption></figure>"
}
```

`insert-body-html` 将易标受限 HTML 转为 Open XML 块，并原地替换 Word 中唯一的块级内容控件 `w:tag=yibiao:body:<target_id>`。目标必须是 `w:sdtBlock`，运行级和单元格级内容控件不作为正文插入位置。动作使用临时副本完成转换和 Open XML 校验，成功后再替换原文件。`image_max_width_percent` 是独立图片的全局最大宽度；`figure` 必须使用 `data-yb-size=square|wide|tall|panorama`，`img` 的 `data-yb-asset-ref` 必须是工作区内相对路径；图片按预设画框居中裁切并保留图注，配图提示 `template` 不写入 Word。

```json
{
  "action": "blind-check-inspect",
  "source": "blind-check/source/<fileId>.docx",
  "profile": {"page": {}, "body": {}, "headings": {}, "table": {}, "structure": {}, "text": {}, "privacy": {}, "props": {}, "consistency": {}, "image": {}, "rules": {}},
  "sensitive_words": [{"text": "某某建设有限公司", "source": "credential"}],
  "image_facts": [{"part": "word/media/image1.png", "color": true, "color_ratio": 0.23}]
}
```

`blind-check-inspect` 是暗标合规检查，代码在 `BlindCheck/`。它只读打开工作区内的 docx 副本：直接按 zip 条目和关系文件定位 part，再用 LINQ to XML 读取，不经过 SDK 的强类型包装，所以畸形超链接关系不会导致文档打不开。`profile` 是 Main 规范并与默认值合并后的完整预设，null 表示该项不检查（招标文件未要求）：`BlindCheckProfile.Bool` 区分缺字段（用兜底值）和 null（不检查），`body.allow_*` 为 null 视为允许，`table.allow_*` 为 null 时同正文；`sensitive_words` 是预设里的自定义敏感词加上资信库企业信息。

- 求值：字体、字号等按 docDefaults → 表格样式 → 段落样式链 → 字符样式链 → 直接格式求实际生效值。主题字体要解析 theme1.xml，ea 为空时按 Hans 等脚本表回退。字体按槽位逐层查找，只写 `w:hint` 的层不会遮住下层。段落标记格式 `w:pPr/w:rPr` 只作用于段落标记，不参与文本块求值。已知简化：粗体、斜体等开关属性按最高优先级一层取值，不做样式层之间的异或切换；表格样式只取顶层 `pPr/rPr`，不合并 `w:tblStylePr` 条件格式（首行、首列、镶边等）。修复写入的是显式直接格式，不受这两点影响；删除隐藏文字是例外，没有直接设置隐藏、又有两层及以上样式都设了隐藏时（`RunFormat.VanishStacked`）开关可能互相抵消、文字实际可见，这种文字只报不删，留给人工。
- 标题：先看目录（TOC 域或 toc 样式）条目，再看标题样式和大纲级别；没有目录时才用"第X章""一、"等前两级编号兜底，请求带 `heading_fallback: false` 时不兜底（删除了目录的修复副本复查时沿用原文的认法，见下文修复）。目录域开始或结束所在的段落，文字全在域外时（例如"域结束 + 分页符 + 标题文字"同一段）算正文不算目录；域外套用目录样式的段落要成片出现，且前面有目录标题或过半以页码结尾才算目录，正文里偶然套用目录样式的段落不算。
- 适用范围：对齐、首行缩进只查正文，图名、表名（40 字以内、"图/表/附图/附表"加编号或标点开头、紧挨图片段落或表格）和目录前单独一行的目录标题（以"目录""目次"结尾的短行，`OutlineAnalyzer.IsTocTitle`）不查；行距、段前段后连标题一起查；加粗、斜体、下划线、颜色、突出显示和文字底纹连表格文字一起查，表格没单独规定时按正文要求。表格彩色底纹和页面背景色归入"不允许使用彩色"，正文不允许彩色文字时才查；图表、SmartArt、形状按填充和线条颜色（含样式默认色、图表自动配色）判断，矢量图提示人工确认。英文标点、多余空格、手动换行、分栏和一致性规则不来自招标文件，一律是低风险建议。
- 标题序号：`structure.heading_numbering` 为 arabic 时检查每个标题的序号——自动编号按 numbering.xml 的编号格式和编号文字级数（`NumberingFormats`，含 lvlOverride 与 isLgl，不展开 numStyleLink），手写编号看开头的"1、""1.1"等；非阿拉伯数字、级数与标题级别不符报中风险，没有序号报低风险，第一个带序号的标题之前没有序号的标题视为文档总标题不报；按编号样式兜底识别的标题只比较是否为阿拉伯数字，不比较级数。文字里直接夹带的换行字符（Word 显示为空格）在手动换行检查里单独说明。
- 规则：共 64 条，按 privacy / structure / image / page / paragraph / font / text / table / consistency 分类，单条规则出错不中断，错误写入 `rule_errors`。结果按"规则 + 严重度 + 结论 + 是否候选"归并，每组保留首尾分布的 6 个样本，另按文档顺序保留前 200 条带段落编号的定位条目（`items[].locator`）供 AI 复核。严重度分 high / medium / low，预设的 `rules.<id>.enabled / severity` 可单条覆盖。
- 候选问题（`candidate`）：规则只能初筛、是否真的违反要求交给 AI 复核判定的问题。一致性规则整条是候选（`RuleSpec.Candidate`）；身份信息里按后缀识别的企业名称、表单字段名、疑似银行账号、占位符是候选（`Finding.Candidate`），敏感词、自称、联系方式、证件号等是确定的事实。候选与非候选分组归并。
- 段落编号（`DocumentModel.Locators`）：正文 `p{序号}`，表格 `t{表}.r{行}.c{列}`（同一单元格多段再加 `.{第几段}`），页眉页脚 `hdr{n}.{k}` / `ftr{n}.{k}`，脚注尾注 `fn.{k}` / `en.{k}`，文本框 `tb{k}`。同一份文件每次建模编号相同，检查结果、标书结构导出和 Agent 编辑都按它定位。
- 一致性规则（`ConsistencyRules`）只在预设对应项为 null（不检查）时兜底：同级标题和正文按多数找少数派，正文中文字体只统计中文文本块；标题编号只看手写编号，按上级标题分组，只报跳号和重号。各节页面设置、对齐到网格、上下标、表格对齐、合并单元格、命名书签、半角括号、全角数字、全角字母九条细项由预设开关控制，默认关闭。
- 封面与手写目录：`structure.skip_cover`（默认开）时，正文开头到第一个分页符或分节符之间、没有标题和表格且不超过 15 段 300 字的内容视为封面，不参与正文格式规则，身份信息和隐藏文字照常检查，统计里返回 `cover_paragraphs`。隐藏文字（`text.hidden`，`AllRegions`）覆盖全部区域：正文、表格、封面、目录、页眉页脚、脚注尾注和文本框都检查，修复同样逐区域删除；字号检查不分中西文，单独成块的数字、西文也按正文字号要求。没有目录域时，前部连续 3 条以上与后文标题文字相同的编号兜底"标题"视为手写目录，归入目录；编号兜底给出的是名义级别，不参与标题层级跳跃判断。表单字段名（联系电话、单位名称等）只在后跟冒号或单独占一个单元格时报出。
- 页眉页脚：页码按 `structure.page_number` 判断（forbid 不得有页码；footer_only 只准出现在页脚，页脚其他内容一律报出；null 不限）。内容按段落取显示文字，文本框按框内文字计入，图片记为"[图片]"，表格按其中的文字计入；可见的段落边框（直接设置优先，再沿段落样式链查找，nil、none 算没有）记为"[横线]"，中文版 Word 的「页眉」样式自带下边框，文字删光后仍会显示；检查和修复共用 `StructureRules.HeaderFooterMarks` 判断是否有内容；有页码域时只含页码的段落算页码不算内容，所以 WPS 插入的页码文本框不会被当成图片。
- 图片：`ImageCatalog` 收集正文、页眉页脚、脚注尾注引用的图片，按 part 去重并定位到首次出现的段落；`ImageFormats` 按文件头识别格式与尺寸，读取 EXIF / XMP / PNG 文本块中的作者、版权等字段和 GPS，提取 EMF（EXTTEXTOUT 与 EMF+ DrawString）、WMF（TEXTOUT / EXTTEXTOUT，ANSI 文字按 GBK 解码）和 SVG 中的文字，再交给身份信息检测。彩色判断要解码像素，助手不做，由 Main 抽样后通过 `image_facts` 传入；统计里的 `images / image_formats / vector_images` 随结果返回。
- 进度写在任务目录的 `progress.json`，内容为 `{frac, label}`，先写临时文件再替换；结果写在 `blind-check-result.json`（蛇形命名），`result.json` 仍只写 `ok/output`。

Main 侧使用独立的 `blind-check` 助手进程（`openXmlHelperService.runBlindCheck`），每 300ms 轮询进度，最长等待 10 分钟。检查结束或取消后结束该进程并删除任务目录，避免空闲进程占着检查大文档时的内存；技术方案重置时调用的 `close()` 不影响它，应用退出时由 `closeBlindCheck()` 结束。运行 `node --test scripts/check-blind-check.cjs`（client 目录）可在中文临时目录中验证继承无误报、各类违规命中、匿名性、目录定标题、一致性、图片元数据与矢量图文字、细项规则、Excel 导出、取消和 4 万段的性能。

```json
{
  "action": "blind-check-fix",
  "source": "blind-check/source/<fileId>.docx",
  "output": "blind-check/fixed/<fileId>.docx",
  "profile": {},
  "sensitive_words": [],
  "image_facts": [],
  "fix_rules": ["struct.doc_props", "font.size", "text.english_punct"]
}
```

`blind-check-fix` 是暗标自动修复，代码在 `BlindCheck/Fix/`。它与检查共用 `BlindCheckSession`（打开文档、建模、识别目录标题与封面），原文件不改动，结果写在 `output` 指定的工作区副本：

- 调度（`BlindCheckFixer`）：不依赖检查阶段已归并的样本，而是在同一模型上逐段、逐文本块重新执行 `fix_rules` 中各规则的检查函数，检查报出问题才调用对应修复。规则开关、适用范围、封面与目录排除和格式目标（`TargetFor`）都与检查一致。
- 写入：直接修改模型里的 XElement。属性元素由 `PropertyWriter` 按 schema 顺序插入（rPr / pPr / sectPr / tcPr / 编号的 lvl），不认识的扩展元素原位保留；关闭类格式写显式关闭值（如 `<w:b w:val="0"/>`），样式继承来的格式才能关掉；改字体时去掉同槽位的主题字体。标点、空格、特殊字符按整段文字计算位置，再按 `DocumentModel.PieceText` 对应回各个 `w:t`。
- 结构类：接受修订（段落标记删除、删除或合并单元格跳过并写入 `notes`）；删除批注连同正文锚点和批注扩展、批注人列表；取消外部超链接并删除关系；身份类域整体删除；隐藏文字直接删除（隐藏来自多层样式叠加的不删，见上文求值）；页眉页脚清空并用无边框覆盖页眉横线，预设允许页码时保留只含页码的段落（含 WPS 插入的页码文本框），保留的段落有横线时同样写成无边框，不再被引用的图片从包里去掉；页面背景色直接删除；文字底纹写显式的"清除、自动"覆盖样式；空段落只删不带编号、不含对象和书签、非封面、非表格间必需、没设段前分页（直接设置或来自样式，删了后文会回到上一页，检查时单独报"存在设置段前分页的空段落"）的段落；只含一个分页符的空段落把分页符挪到上一段末尾后删段，分页符数量和换页位置不变，上一块是表格、目录、带分节符或已在段尾换页的段落（含连续分页留出的空白页）时不动；图片元数据删除 JPEG 的 APP1 / APP13 / COM 段和 PNG 的文本块。
- 手动换行（`TextFixes.SplitLineBreaks`）：在 `w:br`、`w:cr` 和 `w:t` 里夹带的换行字符处拆段，后面的段落复制原段落格式，段前分页只留第一段、分节符留最后一段，拆出的空行并回前一段，新段开头的空格去掉；标题、带编号或图文框的段落、含域的段落以及换行落在超链接、修订等包装里的不拆，写入 `notes`。拆段会搬动文本块，放在逐段修复之后执行。
- 目录（`TocFixes`，只在 `structure.check_toc_present` 为 forbid 时生效）：删除目录域（连同显示结果、嵌套的页码域和 Word 目录库外面的内容控件）、检查认定的域外目录样式条目、以"××目录"标题开头且下面连续 3 行以上都与后文某段文字相同（去掉点导引和页码后比较）的手工目录，以及紧挨着的目录标题；只按点导引和页码认出、没有目录标题的手工目录不删，写入 `notes`。域结束在正文标题里时只删域，标题保留。只靠目录认定、没有标题样式和大纲级别的标题，把目录里的级别写成段落的大纲级别，删掉目录后标题结构不变。删除后整理接缝：前后两块内容之间只保留一处换页，依次优先用分节符（接缝里的分节符移到上一段，避免空段落单独占一页）、前一块的段末分页符、接缝里最前面的分页段落（它也是认封面的分界）、后一块的段首分页符；多出来的空节删除，后续各节沿用的页眉页脚引用补到下一节；原来和目录同页的空段落一并删除；原来换页而删完不换页时在前一块末尾补分页符；删段后并在一起的表格之间补空段落。
- 标题序号（`HeadingNumberFixes`，与检查共用 `StructureRules.HeadingNumbers`）：自动编号把有问题的标题用到的 lvl 改为 decimal 并加 isLgl，编号文字改为与标题级别同级数的 "%1.%2"（保留"、"后缀）；同一抽象编号里"级别序号 − 标题级别"不一致或该级别被正文列表共用时不改。第一个阿拉伯数字标题从 1 开始、它前面带其他序号的同级或上级标题视为总标题，删去序号；全文没有阿拉伯数字序号、手写序号从 1 级逐级展开且同级写法一致时按级别重排为 1、1.1、1.1.1（原序号带"、"的保留"、"，否则后跟空格）。手写序号改动后按 `NormalizeTitle` 找到目录条目一并修改；自动编号改动后目录要在 Word 里更新域，写入 `notes`；其余混用情况只写 `notes`。
- 写出（`DocxWriter`）：按原 zip 条目顺序新建包，只重新序列化改过的 part，其余条目按原内容复制。
- 校验与复查：用 Open XML SDK 分别校验原文件和副本，按"错误类型 + part + 元素"对比，副本多出原文件没有的错误时删除副本并失败；通过后对副本重新开一个会话检查，结果写在 `blind-check-fix-result.json`（`fixes` 每条规则的修改处数、`notes`、`validation`、`after` 复查报告、`heading_fallback`）。删除了目录、而原文按目录认标题时，复查不按编号兜底认标题，`heading_fallback` 返回 false，Main 之后对这份副本的复查、结构导出和编辑都要带上它，否则正文里的编号短句会被认成标题、报出并非修复引入的问题。

AI 复核用的两个动作在 `BlindCheck/Review/`，请求与 `blind-check-inspect` 相同（`source`、`profile`、`sensitive_words`、`heading_fallback`）：

- `blind-check-dump`：导出标书结构（`blind-check-dump.json` 的 `text` 与 `images`）。文本一行一段、以段落编号开头，标出标题级别、目录、封面、段前分页、分页符、分节符、域和所含图片；段内文字与渲染文字逐字对应，只把手动换行、制表符、图片占位换成 ⏎ ⇥ ◇；开头列出各节纸张、页边距、页眉页脚引用和页码起始，文末是图片清单（`img{n}` 按出现位置编号，含名称、替代文字、尺寸和所在段落）。统一用 `\n` 换行。
- `blind-check-edit`：在 `source` 上执行 `edits`（`{op, target, find, replace}`），`original` 为结构校验的基准文档。`replace` 替换段内一处文字，`find` 在展示文字里必须唯一出现，跨越换行、制表符、图片、域等非 `w:t` 内容时拒绝；`delete_paragraph` 删除整段，`find` 须等于该段全文（忽略空白），带分节符或分页符、标题、目录、单元格里唯一的段落不能删；`clear_image_alt` 去掉图片的替代文字和标题。同一批按提交时的编号定位，逐条返回结果；改完与 `original` 对比做 Open XML 校验，有新错误时整批撤销，通过后覆盖 `source` 并返回新的标书结构（删段后编号会变）。

加新动作时：只在助手里增加 `action` 处理，请求和结果仍落在同一任务目录，不改信号格式。

## 开发启动

开发机需要 .NET 10 SDK。Main 未打包时先 `dotnet build`，再拉起 `bin/Debug/net10.0/openxmlhelper`，不要用 `dotnet run`（编译日志会污染 stdout）。

```powershell
dotnet build openxmlhelper\src\OpenXmlHelper\OpenXmlHelper.csproj
```

不要把自包含 exe 提交进 git。

## 打包

用户安装包必须自带运行时，禁止依赖本机 .NET。

- 发布：`--self-contained true`、`PublishSingleFile=true`，不上 Native AOT、不裁剪。
- RID：`win-x64` / `osx-x64` / `osx-arm64`。
- 产物目录名与现有命令工具一致：`win32-x64`、`darwin-x64`、`darwin-arm64`。
- 输出到 `client/vendor/openxml-tools/<platform>-<arch>/`，再由 electron-builder `extraResources` 打进 `openxml-tools/<platform>-<arch>/`。
- 打包前执行 `client/scripts/prepare-openxml-helper.cjs`。Release CI 按当前平台发布。

安装包内拉起：`resources/openxml-tools/<platform>-<arch>/openxmlhelper(.exe)`。

## 客户端接入

整本投标文件导出复用 `render-restricted-html-docx`，请求包含 `html`、`export_format`、`asset_root`、`chrome_assets`，并设置 `whole_document: true`。Main 在内存组装的 HTML 顶层使用 `section[data-yb-export-template][data-yb-export-page-template]` 标记正文样式和页面范围，两项值均为 `true` 或 `false`；目录标题带 `data-yb-outline-number`，按当前树顺序编号，正文内部标题不参与目录计数。这些是程序内部转换标记，不写回 Agent 的源文件。

整本转换在一个 Word 包内完成，按范围应用基础或模板格式；列表编号定义按范围隔离，页面范围切换才分节，无装饰范围显式使用空页眉页脚以阻止继承。章节页框开启时，完成正文、列表、图片和业务表格格式化后，把任意两级标题之间的内容融合为一张平面表格；业务表格行并入统一网格，保留合并单元格，不嵌套、不单独重复业务表头。无标题的小节也融合，不能跨越模板样式范围或页面分节；正文行可拆页，图片整体换页或换栏。标题始终保留为顶层段落，`heading_border.include_headings` 默认及缺省均为 `true`，关闭仅去掉标题边框，底纹、缩进、导航和其他格式不变。未开启章节页框时，横版双栏继续复用一级标题通栏逻辑；页码起始值只写一次。

生成的文档在 `settings.xml` 声明兼容模式 15（`w:compat/w:compatSetting compatibilityMode=15`）。满宽业务表格和章节页框表格的 `tblW` 统一为 `pct 5000`（栏宽 100%），列网格仍按导出时的栏宽计算、只作列比例；用户在 Word 中调整页边距后，正文框与标题段落边框同步移动，双栏时按单栏宽计算。不要去掉兼容模式或把表宽改回 dxa：不声明时 Word 按 2007 规则排版，百分比表格会把单元格左右边距加在栏宽之外，写死的 dxa 表宽改页边距后又与标题边框错位。docx-editor 不读取兼容模式，按正文宽度换算百分比，预览和格式自检口径不变。已知差异：Word 实际绘制的段落边框外沿比规范位置再外扩约 1.45pt，docx-editor 按规范绘制；现有 115 twips 留白与 5pt 间距以预览完全对齐为准，Word 中标题框每侧比正文框宽约 1.5pt。图片为绝对尺寸，调大页边距后超宽图片需在 Word 中自行缩放。

Main 使用正式助手队列，最长等待 30 分钟；普通小节和模板样张不传 `whole_document`，沿用预览队列并共享同一套页框转换逻辑。图片通过既有临时中转目录传入，成功转换后 Main 才写入用户选定的目标文件。

受限 HTML 配图按文件头识别 PNG、JPEG、GIF、BMP、WebP、TIFF、EMF、WMF（含可放置与标准 WMF），尺寸读取与 Word 图片部件声明使用同一真实格式，不依赖文件后缀；EMF 取头记录 rclFrame，WMF 取可放置头边界框或 SetWindowExt，TIFF 取首个图像目录宽高。后缀与内容不一致的图片保持原始字节插入，不重命名、转码或修改源图片。文件头可识别但读不到尺寸时按画框尺寸放置、不裁切。文件头无法识别时，若 `render-restricted-html-docx` 请求的 `asset_types`（Main 在中转图片时按扩展名用 mime-types 声明，键为 `data-yb-asset-ref`）给出上述八种以外的 `image/*` 类型，则按该类型原样嵌入、按画框尺寸放置，交给 Word 显示；声明为可核对格式而文件头不符，或没有声明，视为无法导出。单张图片无法导出（文件不存在、格式无法识别或读取失败）时，在原位置写入“[图片无法导出：alt]”并保留图注，其余正文照常转换，`result.json` 的 `imageWarnings` 按图片返回 `assetRef` 与 `reason`；`insert-body-html` 同样返回。figure 结构、引用路径等结构错误仍直接失败。运行 `node scripts/check-technical-plan-export.cjs` 检查整本与小节转换中的八种格式、格式错配、Word 图片类型、尺寸比例、尺寸兜底、未知格式原样嵌入和坏图原位提示。

“首页不同”为封面预留，整本导出尚未接入封面，因此 `whole_document: true` 时忽略 `first_page_different`：不写 `w:titlePg`，不创建首页专用的空白页眉页脚；第一页按所在范围的普通页面规则排版。用户配置保持原值，普通小节转换和模板样张仍遵循该设置。

客户端目录运行 `node scripts/check-technical-plan-export.cjs --ipc` 可同时检查真实转换和独立 Electron 窗口中的 preload、IPC、保存、进度及取消链路。

- 路径：`client/electron/utils/paths.cjs`
- 服务：`client/electron/services/openXmlHelperService.cjs`
- Agent 工具：`client/electron/services/pi/piOpenXmlTool.cjs`
- 退出：挂在 `ipc/index.cjs` 的 `closeServices()`
- 任务串行排队；`ping` 超时 15 秒；助手崩溃则当前任务失败，下次再拉起。
- stderr 走开发者日志，模块名 `openxml-helper`。

格式自检继续使用同一整本转换动作。Main 仅在自检副本的每个目录标题和 AI 正文顶层块之前加入 `YIBIAOLAYOUT:yb_layout_<序号>` 定位段落；`RestrictedHtmlDocumentRenderer` 在格式化前删除该段落，并在对应 Word 块首段插入零宽书签。书签不增加段落或可见文字，映射由 Main 在内存持有，不写回正文 HTML，正式导出不带这些标记。双栏通栏一级标题之后，最终双栏正文的节属性也必须显式为 continuous；不能依赖缺省 nextPage，否则最后一章会出现标题独占一页。

## 不要做

- 不要改成 HTTP、gRPC 或命名管道。
- 不要在信号里夹文档内容或大 JSON。
- 不要让安装包依赖用户机器上的 .NET。
- 不要解析 `.doc` / `.wps`；先转成 `.docx` 再交给助手。
