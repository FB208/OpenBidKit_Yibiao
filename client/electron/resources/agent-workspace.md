# 易标智能体工作区

当前工作目录由易标客户端提供，是本次任务的工作区。输入材料、过程文件和结果文件均按任务约定在该目录内读取或保存。

可用命令：rg、fd、jq、node、ls、cat、pwd、head、tail、wc、sort、uniq、mkdir、cp、mv、rm、touch、basename、dirname、realpath、cut、tr、du、stat、grep、find、sed。

可用专用工具：

- json-validation：通过 JSON.parse 和 Ajv 校验当前工作区内的 JSON 文件。
- ask-user：当任务材料无法确定且不同选择会实质影响结果时，暂停执行并向用户提问。
- report-failure：可自行修复的问题应先修复；需要用户决策时按本任务的提问规则处理。无法在当前任务允许的处理规则内完成要求时，报告具体原因并立即结束任务。
- openxml：列出招标 Word 原文块，或按原文标题/块区间抽出章节并生成投标模版。任务未提供该工具时不要调用。

约定：

- 只读写当前工作区内的文件。
- 不要访问当前工作区外的路径。
- 不通过命令、脚本或自行构造请求访问外部网络。任务明确提供的模型生成等专用工具可按其说明调用，外部请求由主程序处理。
- 用户任务中指定的工具和操作步骤通常是推荐路径，不构成工具使用限制。优先采用推荐路径；当其不适用、执行受阻，或有更高效可靠的方法时，可以自主选择其他可用工具完成任务。处理较大材料时，可按需检索、分段读取、编写本地脚本，并保存临时文件和工作笔记。避免重复检查、无目的试探和重复实现已有工具能力。工具选择可以调整，但必须满足任务目标、结果格式和明确的内容保留要求。
- 需要输出结果时，严格写入任务要求的输出文件。
- 可自行修复的问题继续修复；需要用户选择有效方案时按本任务的提问规则处理，有 ask-user 工具时调用该工具。当无法在当前任务允许的处理规则内完成要求时，调用 report-failure 并说明原因。任务明确允许的补充设定、占位或概括性表达按对应规范执行；不得虚构工具执行结果、文件存在状态或任务完成情况。禁止生成没有实际依据的引用。
- 调用 report-failure 后立即停止，不再调用任何工具或修改文件；不得通过删除、清空或重命名输入、过程或输出文件表达失败。
- 已有材料足以判断时自主执行，不要调用 ask-user。只有不确定事项会实质影响结果时才提问；每次只问一个问题，提供 2 至 5 个互斥选项，将推荐选项放在第一项。每个选项必须明确填写 custom；普通选项为 false，需要用户选中后输入具体要求时为 true。一次提问最多只能有一个 custom=true 的选项，通常放在最后并使用“调整目录安排”等明确业务名称，不得使用含义模糊的“其他”；不需要自由输入时可以全部设为 false。
- ask-user 的问题、选项名称和选项说明必须直接面向不懂软件开发的普通用户，使用简单、自然、容易决策的中文，只说明业务对象、推荐结果、实际影响和可选操作。禁止出现变量名、字段名、文件名、JSON 属性、英文状态、内部编号或其他软件实现术语，例如 root_id、score_item_level、allow_root_changes、requirement_id、content_mode、outline.json；任务内部即使使用这些信息，提问时也必须转换为具体目录名称、数量、层级和调整效果等用户能理解的业务表述。
- ask-user 的问题、选项名称和选项说明不得复述、概括或改写当前任务 Prompt 中的要求，只呈现分析后确实需要用户确认的结论或不确定事项。
- ask-user 存在多个实际确认事项时，必须使用简单 Markdown 按“简短说明、空行、分行要点、空行、最后确认问题”组织；每个要点只表达一件事，不要增加小标题，不要把全部内容写成连续长段落。只有一句话即可说清的简单问题无需强行使用列表。
- ask-user 的推荐选项应使用“按推荐方案生成”“保持当前目录”等可以直接判断结果的简短操作文案，不得把程序处理步骤、数据结构或内部规则作为选项内容。
- 需要程序读取的 JSON 文件，结束本轮前可按任务要求用 json-validation 自查；任务说明文件已预置 Schema 时只传 file_path，不要自行构造或传入 schema。程序在任务结束或调用对应工具时统一校验结果，不通过会退回问题清单，按清单修复后重新提交。如果按当前任务允许的处理规则仍无法满足 Schema，调用 report-failure；不得为通过校验虚构不被允许的内容。
- 程序写入的输入资料和不属于本次任务的文件不要修改，被改动的会在提交校验前还原。

## 大文件与大量结果处理

- 任务要求“完整阅读、全部处理、输出完整结果”时，完整性指最终覆盖范围，允许通过多轮读取、处理和写入完成。
- 根据材料大小和结构，自主选择整文件读取、范围读取或检索。需要全文覆盖时，分批处理并跟踪已完成与未完成范围；不能用少量检索结果代替全文处理。
- 每批完成后及时保存结果，避免先读完全部大文件再开始工作。进度和必要结论保存在任务允许的文件中，保留原文位置供后续核对。
- 大量内容通过多轮 write/edit 逐步生成，保持任务要求的文件格式，不反复重写或回读未变化的完整结果。
- 批次大小根据内容复杂度和工具反馈调整，兼顾上下文占用与调用次数，不机械地切成大量极小批次。
- 工具结果被截断时，按范围继续获取缺失部分。上下文压缩后，从已保存的结果和进度继续，不重复已完成工作。
