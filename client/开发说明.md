# 易标投标工具箱开发说明

本文面向参与 `client/` 开发的成员。具体功能行为以当前代码为准；本文只保留能帮助定位代码、跨进程协作、复用 UI、维护持久状态和完成验证的稳定规则。

## 快速开始

仓库根目录没有客户端 `package.json`，所有客户端命令先进入 `client/`：

```powershell
cd client
npm ci             # 安装依赖；postinstall 会按当前 Electron 重建 native 模块
npm run dev        # Vite 127.0.0.1:5173 启动后打开 Electron
npm run build      # tsc --noEmit && vite build
```

- CI 使用 Node 22，排查本地与发布构建差异时优先对齐该版本。
- `better-sqlite3` 是 Electron native 依赖。出现 `NODE_MODULE_VERSION` 不匹配时运行 `npm run postinstall`；验证 ABI 用 `npm run smoke:electron-native`，不要用普通 Node 进程加载 Store 代替。
- 项目没有统一 lint 脚本，也没有覆盖全项目的 test 脚本；现有 `*.test.cjs` 需按改动范围用 `node --test <file>` 定向执行。

## 运行结构

```text
src/main.tsx
├─ 开发者独立窗口（由 ?window=... 选择）
└─ AppProviders
   └─ WorkspaceDatabaseGate
      └─ App
         └─ AppShell + AppRouter

Renderer
  └─ window.yibiao
      └─ electron/preload.cjs
          └─ electron/ipc/*.cjs
              └─ electron/services/*.cjs
                  ├─ SQLite Store / 配置
                  ├─ 文件与导出
                  └─ AI / Agent / 后台任务
```

- Renderer 是 Vite + React + TypeScript ESM；Electron Main、preload、IPC 和 Main 服务是 CommonJS，保持 `.cjs`。
- 主窗口启用 `contextIsolation`、关闭 `nodeIntegration`。Renderer 不导入 `electron`、`fs`、`path`，也不直接使用 `ipcRenderer`，本地能力统一通过 `window.yibiao`。
- Renderer 负责页面状态和交互编排；Main 负责配置、SQLite、文件解析、AI、Agent、后台任务、导出、插件和更新。
- `WorkspaceDatabaseGate` 在数据库检查、迁移和历史清理完成前阻止业务页面挂载；数据库相关 IPC 也会先注册为 pending/unavailable handler。
- `AppRouter` 是基于 `SectionId` 的组件分发，不是 URL 路由。不要按 React Router 的约定添加页面。

## 代码放在哪里

| 位置 | 职责 |
|---|---|
| `src/app/` | 应用级路由、菜单、全局 Provider、数据库 Gate、启动提示与状态条 |
| `src/components/` | 应用壳层组件，目前主要是 `AppShell`、`Sidebar` |
| `src/features/<feature>/` | 功能页面及其专用组件、Hook、类型和 Renderer 轻量编排；目录按实际复杂度创建，不补空层级 |
| `src/shared/ui/` | 跨功能 UI 组件和全局交互 Provider |
| `src/shared/types/` | 跨功能类型、导航类型和 `window.yibiao` bridge 类型 |
| `src/shared/prompts/` | 仍在 Renderer 使用的 Prompt builder |
| `src/shared/utils/`、`src/shared/markdown/` | 跨功能纯工具和 Markdown 渲染辅助 |
| `src/styles/` | token、壳层、共享组件和各 feature 样式；`src/styles.css` 是唯一总入口 |
| `electron/main.cjs` | 窗口、协议、应用生命周期和 Main 入口 |
| `electron/preload.cjs` | 主窗口 bridge；拖拽文件路径也在这里通过 `webUtils` 暴露；插件配置窗另用 `preload-plugin-config.cjs` |
| `electron/ipc/` | IPC 注册与参数转发；`index.cjs` 负责服务装配和数据库生命周期 |
| `electron/services/` | Main 业务服务、Store、任务实现；`agent/`、`pi/`、`doc2markdown/` 是专用子层 |
| `electron/utils/` | Main 纯工具、路径、日志、队列、文本编辑和导入图片清理 |
| `electron/resources/` | 打包进入客户端的 Agent 指令、许可证公钥和构建证明 |
| `vendor/agent-tools/`、`scripts/` | 随包 Agent 命令工具及构建/校验脚本 |

放置原则：

- 只被一个功能使用的代码留在该 feature；出现真实跨功能复用后再上移 `shared/`。
- `shared/` 的运行时代码不要依赖 feature。现有 `shared/types/ipc.ts`、`shared/types/index.ts` 会组合或转出部分 feature 类型，这是 bridge/type 边界的现状，不应扩展成 shared 引用 feature 组件或服务。
- Renderer 的 `services/` 只做 bridge 调用或轻量编排；耗时流程和权威持久化放 Main。
- 新业务 IPC 默认保持薄。`ipc/index.cjs` 的生命周期装配以及 `pluginIpc.cjs` 的现有插件市场/配置编排是例外，不要把它们复制成普通功能模板。
- Prompt 不写进组件：Renderer Prompt 放 `src/shared/prompts/`，Main 后台任务的 Prompt 与对应任务服务放在一起。

### 新增菜单页面

至少同步检查以下位置：

1. `src/shared/types/navigation.ts`：增加 `SectionId`。
2. `src/app/menuConfig.ts`：配置一级或二级菜单。
3. `src/app/AppRouter.tsx`：注册页面分发。
4. `src/components/Sidebar.tsx`：为 `navigationIcons` 补齐图标映射。
5. `analytics/dashboard/public/src/pages/traffic.js`：为新增埋点路由补中文显示名。

一级菜单有 `children` 时，`AppRouter` 会使用 `shared/ui/SecondaryMenuPage.tsx` 显示二级入口，不在侧边栏实现展开菜单。设置页是侧边栏底部的独立入口。

## Renderer 与 Main 协作

新增或修改 bridge API 时按完整链路更新：

1. 在 `electron/services/` 实现业务能力或 Store 操作。
2. 在对应 `electron/ipc/*Ipc.cjs` 注册通道，并在 `electron/ipc/index.cjs` 装配依赖。
3. 若通道依赖工作区数据库，同时加入 `index.cjs` 的 `workspaceDatabaseChannels`，确保数据库就绪前不会漏注册或重复注册。
4. 在 `electron/preload.cjs` 暴露方法或事件。
5. 在 `src/shared/types/ipc.ts` 同步参数、返回值和事件类型；全局声明由 `src/vite-env.d.ts` 引用该类型。

其他约定：

- `onXxx` 事件 API 必须返回取消订阅函数，React effect 卸载时调用。
- 受管任务页面先读取 Store 快照，再订阅 `tasks.onTaskEvent()`，随后调用 `tasks.getActiveTasks()`；后一步会再次订阅并回放活动任务，避免首次事件早于 listener 注册。
- IPC patch 以“字段是否存在”为语义：字段缺失表示保留，字段出现表示应用该值；`undefined`、`null` 或空集合通常用于显式清理，具体由对应 Store 定义。Renderer 合并 patch 时使用 `hasOwnProperty`，不要用 truthy 判断。
- 命令接口可能返回 `void`、实体或局部 patch，不假定每次写入都会返回完整工作区；需要全量状态时显式调用 `load*` / `get*` / `list*`。
- 拖拽得到的浏览器 `File` 通过 `window.yibiao.file.getPathForFile(file)` 转为本地路径，不读取非标准 `file.path`。
- 外部链接通过 `window.yibiao.openExternal()`；本地导入图和生成图使用 Main 注册的 `yibiao-asset://imported-images/...`、`yibiao-asset://generated-images/...`，不要向 Renderer 暴露 `file://` 路径。
- 只在用户输入和外部响应边界做必要校验；Renderer、preload、IPC、service 之间不重复堆叠同一套内部参数校验。

## 数据与后台任务

### 持久化位置

| 数据 | 位置 / 权威实现 |
|---|---|
| 用户配置与 API Key | `userData/user_config.json`，由 `configStore.cjs` 管理 |
| 结构化业务状态 | `userData/workspace/yibiao.sqlite` |
| 导入/解析源 Markdown、图片及文件型产物 | `userData/workspace/<feature>/`、`imported-images/`、`generated-images/` |
| Pi 运行环境和持久任务 | `userData/agent-runtime/pi/` |
| 开发诊断日志 | `userData/logs/` |
| 插件与插件配置 | `userData/plugins/`、`userData/plugin-configs/`、`userData/plugin-states.json` |

- 核心工作区、配置、日志和 Agent 路径集中在 `electron/utils/paths.cjs`；新增核心路径优先补在这里。插件自身路径目前由插件服务管理。
- Main 文件读写显式使用 UTF-8，并以 Windows 中文路径为常规场景。
- SQLite 建表、升级、健康检查和备份逻辑以 `electron/services/sqliteDatabase.cjs` 为运行时权威。改表时增加 migration，并同步仓库根目录 `sql/workspace_schema.sql` 的目标结构。
- 数据放 SQLite 还是文件系统由对应 Store 定义：导入源 Markdown 和图片通常是文件，技术方案正文则以 `technical_plan_outline_nodes.content` 为权威。不要按文本大小另建平行 JSON 缓存；删除文件型资源时同步清理其导入图片 scope。
- 不在 Renderer 保存业务状态、草稿或密钥。当前 `localStorage` 只用于远程公告已读标记，以及旧 analytics client id 向配置文件迁移。

### 长任务模型

`taskService.cjs` 统一管理技术方案、标书查重和废标检查任务；三个业务组当前均为组内互斥。知识库是明确例外：`knowledgeBaseService.cjs` 按文档维护 preparation/matching 活动集合，并通过 `knowledge-base:event` 推送。Word 导出也有独立的进度事件。

受管任务遵循以下流程：

1. Main 创建 running 任务并持久化初始状态。
2. 无恢复价值的高频进度调用 `updateTask()`，只更新 Main 内存并推送事件。
3. 阶段结果调用 `checkpointTask(taskPatch, workspacePatch, eventPatch)`，在 Store 事务中一次提交任务和业务 patch，成功后再推送同一份局部事件。
4. 页面卸载不取消任务；重新挂载从 Store 和活动任务回放恢复展示。
5. 应用重启后的恢复策略由 `taskService.cjs` 按任务类型决定：正文任务可转为 paused，目录等待选择仅在持久 Session 完整时恢复，其余中断任务通常转为 error。Renderer 不自行把残留 running 状态改成 idle。

会清空任务或下游结果的 Main 命令，必须先取消相关活动任务并等待 runner settled，再提交 Store；取消后的 runner 不得继续 checkpoint。技术方案和废标检查的导入、删除、重置已经通过 `taskService` 的 `beforeCommit` 链路处理，新入口应复用该模式。

## 技术方案关键不变量

`technical-plan` 与 `existing-plan-expansion` 两个入口共用 `TechnicalPlanHome.tsx`、各 Step 页面、同一套 Store 和任务事件，只由 `workflowKind` 区分。修改共用页面时必须同时验证两个入口，不复制流程页面。

容易遗漏的状态规则：

- 招标文件的完整合并原文保存在 `technical-plan/tender-original.md`，当前投标范围工作副本是 `tender.md`，单份来源 Markdown 在 `tender-files/`；切换标段会从原文重建工作副本并清空下游。
- 目录结构和正文的权威来源是 `technical_plan_outline_nodes`，Renderer 对应 `outlineData.outline[*].content`；`contentGenerationSections` 主要保存生成状态和错误，Word 导出传入的也是目录树正文。
- `outlineWordControlOptions` 是当前可编辑配置，目录成功时固化为 `outlineWordControlSnapshot`；正文生成只使用生效快照。只改当前配置不会改变已生成目录对应的正文目标。
- `saveOutline()` 的 `reason` 是持久化协议：`replace` 清空全部旧正文；`edit`、`delete`、`add-root`、`add-child` 结合 `idMap` / `affectedNodeIds` 只清理受影响节点并保留其他正文；`sort` 会重映射节点、正文状态、运行时和图片引用，不清空已生成内容。不要省略 `reason`，否则 Store 会按 `replace` 处理。
- 所有非 `sort` 的目录变更都会使正文任务/runtime 和全文图片计划失效；纯排序保留并重映射。编辑全局事实会清空正文生成状态；手工改正文或正文配图配置会清空全文图片计划。这些失效操作由 Main Store 完成，Renderer 不另写一套清理规则。
- 正文任务处于 running、pausing 或 paused 时，Store 禁止目录变更和手工正文保存，避免破坏可恢复状态。

Mermaid 以 Markdown `mermaid` 代码块持久化。Renderer 由 `MarkdownRenderer` 本地预览，Word 导出由 Main 的 `localImageRenderService.cjs` 本地转图，不依赖在线 Mermaid 服务。

## UI 与样式复用

UI 使用全局 CSS + Radix primitives，不使用 Tailwind。优先从 `src/shared/ui/index.ts` 引入：

| 场景 | 复用入口 |
|---|---|
| 页面底部操作 | `FloatingToolbar` |
| 对话框、开关、提示 | `AppDialog`、`AppSwitch`、`useToast` |
| 上传区 | `UploadBoard`、`UploadRow`、`UploadFilePill`、`UploadEmpty` |
| 进度、加载、空态 | `ProgressBar`、`InlineSpinner`、`EmptyState` |
| Markdown | `MarkdownRenderer`、`MarkdownEditor`、`MarkdownFullscreenViewer` |
| 全局特殊交互 | `AgentQuestionDialogProvider`、`AiHttpErrorDialogProvider`、`DocumentParseNoticeProvider` |

- `AppProviders` 已挂载全局 Provider，feature 使用对应 Hook，不重复创建全局弹窗或提示状态。
- 成功、错误和普通提示使用 `useToast()` 的 `success`、`error`、`info`；不要使用 `alert`、`window.confirm` 或 `window.prompt`。需要确认或长文案时使用 `AppDialog`/Radix Dialog 和共享按钮类。
- 复用 `.primary-action`、`.secondary-action`、`.danger-action`、`.text-button`、`.panel`、`.section-kicker` 等基础类；颜色、圆角、阴影、焦点和动效优先使用 `styles/tokens.css` 的 `--yb-*` 变量。
- 新 feature 样式放 `styles/feature-<name>.css` 并在 `styles.css` 的 feature 区导入；共享样式才进入 `shared-*.css`。总入口的 `tokens → layout → shared → feature` 顺序参与 CSS 优先级，不随意重排，也不要照搬开发者测试页中的内联视觉样式。
- `body` 固定 `overflow: hidden`。页面根节点保持 `width/height: 100%`、`min-height: 0`，滚动放在页面内部；`FloatingToolbar` 是覆盖层，不为它预留大段底部空白。
- `MarkdownRenderer` 当前默认 `allowRawHtml=true`，调用方不要依赖默认值：远程公告、Agent/AI 文本及其他非本地可信内容显式传 `false`；只有确需保留本地解析 HTML 结构时才传 `true`。
- 所有用户可见文案使用中文，并给失败状态提供可操作信息。

## AI、Agent、文件与日志

- 业务模型请求统一经过 `electron/services/aiService.cjs`。它集中处理模型配置、文本/生图独立队列、并发、重试、取消、日志、Token 统计和埋点；Main 业务代码不要直接请求模型 HTTP。
- `taskService` 为任务绑定 `queueScopeId`、取消信号以及 scoped `aiService` / `agentService`。暂停或取消应沿该作用域传播，不在业务任务里复制队列。
- Pi 只有一个 runtime，`agentService.cjs` 负责全局 FIFO；`services/agent/` 和 `services/pi/` 只实现 Runtime、Proxy、Session、工具、诊断和持久任务，不引用业务 Store 或业务 Prompt。业务适配器通过 `agentService` 公共接口调用。
- 普通 Agent workspace 是临时目录；目录生成 V2 使用持久 task workspace/Session 才能在一级目录确认阶段恢复。结构化 Agent 输出的 Schema 定义在业务任务代码中，通过 `json_validation_schemas` 注入，Agent 调用 `json-validation` 时只传 `file_path`。
- Agent 提问由全局 `AgentQuestionDialogProvider` 和 Main 的问答/自动确认服务承接，feature 不实现第二套等待 Promise 或弹窗。
- 新的文档导入优先复用 `fileService.cjs` / `parseDocumentWithConfig()`，保留配置中的本地或 MinerU 选择、格式 fallback、图片 scope 和统一错误文案。涉及 LibreOffice 缺失提示时复用 `DocumentParseNoticeProvider`。
- Word 导出统一走 `exportService.cjs` 和 `window.yibiao.export.onWordExportProgress()`；Mermaid/HTML 转图由 Main 本地完成。
- AI 返回的局部文本修改复用 `electron/utils/textEdit.cjs`：未知位置用 `applyTextEdit()` / `applyTextEdits()` 并保持唯一命中，已知范围用 `applyRangeEdit()` / `applyRangeEdits()`；未命中或多命中应返回错误，不把替换内容静默追加到末尾。
- 排查异常先记录可复现的阶段、输入摘要和错误链：开发者模式模块日志使用 `createDeveloperLogger()` 写到 `userData/logs/<module>/`，AI 请求日志在 `userData/logs/ai/`。可丢弃文件日志通过 `silentFileLog.cjs` 异步写入，日志失败不得影响主流程。

## 仓库级关联代码

`client/` 不依赖仓库内其他旧前后端目录。只有以下仓库级代码需要按改动联动检查：

| 目录 | 何时查看 |
|---|---|
| `analytics/worker/` | 修改事件、字段、模型统计、Agent 运行统计或失败诊断上传协议时 |
| `analytics/dashboard/` | 新增页面路由、配置统计维度或调整 Dashboard 展示时 |
| `sql/workspace_schema.sql` | 修改 `sqliteDatabase.cjs` migration 或目标表结构时；运行时仍以 migration 为准 |
| `.github/workflows/release.yml`、`.github/scripts/` | 修改打包目标、产物命名、构建证明、更新清单或发布渠道时 |

Renderer 埋点入口是 `src/shared/analytics/analytics.ts`，AI 与 Agent 统计分别在 Main 的 `aiService.cjs`、`services/agent/`。埋点失败必须静默，不影响主流程，也不得删除或绕过现有统计。普通 `/track` 埋点不得上传 API Key、Prompt、模型响应、文件内容、文件名或本地路径；Agent 最终失败诊断是独立 `/agent-errors` 链路，由专用进程采集并脱敏诊断包，不得并入普通埋点或随意弱化。新增菜单页面时完成前述 Dashboard 中文名映射。

## 验证清单

| 改动范围 | 最低验证 |
|---|---|
| Renderer / TypeScript | `npm run build` |
| CSS / 页面布局 | `npm run build`，再 `npm run dev` 检查目标窗口尺寸、内部滚动、Dialog 和 FloatingToolbar |
| Main / preload / IPC | 对每个改动的 `.cjs` 执行 `node --check <file>`，再运行 `npm run build` |
| IPC 事件、文件选择、导入、导出、窗口 | 上述命令后用 `npm run dev` 手动走完整链路，并确认取消订阅和进度回放 |
| Store / migration / 后台任务 | 上述命令 + `npm run smoke:electron-native`；手动验证保存、重启恢复、清空与中断状态 |
| 有对应 `*.test.cjs` 的模块 | `node --test <test-file>` |
| 依赖变更 | `npm ci`、`npm run build`、`npm audit` |
| Windows / macOS 打包 | `npm run dist:win` / `npm run dist:mac`；产物在 `release/` |
| Agent 工具或打包内容 | 对应运行 `scripts/verify-agent-tools.cjs`、`scripts/verify-packaged-agent-tools.cjs` |

`npm run build` 出现既有 chunk 体积警告但退出码为 0 时仍算成功。涉及文件路径时至少覆盖 Windows 中文目录；涉及持久任务、IPC 或窗口生命周期时，单纯编译通过不等于验证完成。
